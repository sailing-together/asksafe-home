# P7.2 Guided Clarification Interaction Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Step 2 ask one useful, rule-owned clarification question for thin risky context, while skipping extra conversation for hard-stop cases.

**Architecture:** Extract the Step 2 interaction decision into a pure deterministic helper that calls the existing `analyze()` function and consumes the P7.1 `SafetyResult.clarification` field. Keep the React component local-state driven and preserve the existing `onSubmit(message, requests)` contract.

**Tech Stack:** Next.js App Router, TypeScript, React, Node test runner, existing AskSafe deterministic safety rules.

---

## Scope

This plan implements the P7.2 design spec:

- `docs/superpowers/specs/2026-06-23-p7.2-guided-clarification-interaction-design.md`

This plan does not add a generic chatbot, new Bedrock follow-up generation, backend persistence, authentication, or result-page redesign.

## File Structure

- Create `lib/guided-clarification-interaction.ts`
  - Owns the deterministic Step 2 assistant response decision.
  - Exports a small function that can be tested without React.
  - Calls `analyze(message, category, requests)` and uses `result.clarification`.

- Create `lib/guided-clarification-interaction.test.ts`
  - Covers the product behavior from the P7.2 spec.
  - Uses the Node test runner, matching existing test style.

- Modify `components/situation-input.tsx`
  - Removes local risk-signal reply branching from `buildAssistantReply()`.
  - Uses the new helper after each user detail is submitted.
  - Tracks whether the one clarification has already been asked.

- Modify `docs/operations/production-smoke-tests.md`
  - Adds a manual Step 2 UI smoke check for guided clarification.
  - Keeps production test wording synthetic and privacy-preserving.

```ts
import { analyze, type Category, type RequestType } from "./analyze.ts"

export type GuidedClarificationInteraction =
  | {
      type: "clarification"
      question: string
      helperText: string
      reason: string
    }
  | {
      type: "acknowledgement"
      text: string
    }
  | {
      type: "hard-stop"
      text: string
    }

export type GuidedClarificationInteractionInput = {
  message: string
  category: Category
  requests: RequestType[]
  hasAskedClarification: boolean
}

const CLARIFICATION_HELPER_TEXT =
  "You can answer this, or choose the safer next step now."

const READY_ACKNOWLEDGEMENT =
  "Thank you. I have enough to show the safer next step."

const HARD_STOP_ACKNOWLEDGEMENT =
  "I have enough to show the safer next step."

const HARD_STOP_SIGNAL_IDS = new Set([
  "code-request",
  "remote-access",
  "personal-details",
])

export function getGuidedClarificationInteraction({
  message,
  category,
  requests,
  hasAskedClarification,
}: GuidedClarificationInteractionInput): GuidedClarificationInteraction {
  const result = analyze(message, category, requests)

  if (hasHardStopSignal(result.riskSignals)) {
    return {
      type: "hard-stop",
      text: HARD_STOP_ACKNOWLEDGEMENT,
    }
  }

  if (hasAskedClarification) {
    return {
      type: "acknowledgement",
      text: READY_ACKNOWLEDGEMENT,
    }
  }

  if (result.clarification?.needed) {
    return {
      type: "clarification",
      question: result.clarification.question,
      helperText: CLARIFICATION_HELPER_TEXT,
      reason: result.clarification.reason,
    }
  }

  return {
    type: "acknowledgement",
    text: READY_ACKNOWLEDGEMENT,
  }
}

function hasHardStopSignal(
  riskSignals: Array<{ id: string; severity: "high" | "caution" }>,
): boolean {
  return riskSignals.some((signal) => HARD_STOP_SIGNAL_IDS.has(signal.id))
}
```
