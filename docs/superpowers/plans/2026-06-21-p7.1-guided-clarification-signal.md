# P7.1 Guided Clarification Signal Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a deterministic clarification signal to AskSafe results so the product can ask one useful verification question when the user gives thin but risky context.

**Architecture:** `assessSafetyInput()` remains the rule-owned source of risk signals and follow-up intent. `analyze()` maps that deterministic assessment into `SafetyResult.clarification`, the API carries the field unchanged, and the result screen shows a compact “Before you decide” card. Bedrock may receive the clarification metadata as context for wording, but Bedrock does not decide risk or whether clarification is needed.

**Tech Stack:** Next.js App Router, TypeScript, React, lucide-react, Node test runner, existing deterministic safety rules, existing Bedrock assist path.

---

## Scope

Implement the minimal data and UI path from the P7.1 design spec:

- add an optional `clarification` object to `SafetyResult`;
- produce clarification only from deterministic rule signals;
- skip clarification for hard-stop cases where the user should immediately stop;
- preserve the existing API response shape except for the additive field;
- show a short result-page card that helps the user verify before acting.

Do not redesign the Step 2 chat UI in this plan. That belongs to a separate P7.2 interaction task.

## File Structure

- Modify `lib/analyze.ts`  
  Owns `SafetyResult`; maps `assessSafetyInput()` output into final safety guidance.

- Modify `lib/analyze.test.ts`  
  Adds deterministic unit coverage for clarification presence and absence.

- Modify `lib/server/bedrock-explanation.ts`  
  Extends `BedrockAssistPayload` so Bedrock wording has the clarification context without owning the decision.

- Modify `lib/server/analyze-route.ts`  
  Passes clarification metadata into the Bedrock assist payload.

```ts
function buildClarification(
  ruleAssessment: ReturnType<typeof assessSafetyInput>,
): SafetyClarification | undefined {
  const signalIds = new Set(ruleAssessment.riskSignals.map((signal) => signal.id))

  if (hasHardStopSignal(signalIds)) {
    return undefined
  }

  if (signalIds.has("family-money-request")) {
    return {
      needed: true,
      question:
        "Before you decide, check one thing: how did they contact you, and how do they want the money sent?",
      reason: "A money request from someone close should be verified another way before you act.",
    }
  }

  if (signalIds.has("payment-request")) {
    return {
      needed: true,
      question:
        "Before you decide, check one thing: who is asking, and how do they want you to pay?",
      reason:
        "The request involves payment, but the person and payment method still need checking.",
    }
  }

  return undefined
}

function hasHardStopSignal(signalIds: Set<string>): boolean {
  return (
    signalIds.has("code-request") ||
    signalIds.has("remote-access") ||
    signalIds.has("personal-details")
  )
}
```

- [ ] **Step 5: Include clarification in every result**
