# P8.6 SES Setup Email Delivery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Deliver real optional setup one-time codes through Amazon SES while keeping AskSafe usable without sign-in.

**Architecture:** Keep the existing setup API contract and replace the placeholder email adapter with a provider-based SES adapter. Terraform adds a small SES setup email module and extends the existing runtime IAM policy with least-privilege send permission.

**Tech Stack:** Next.js App Router, TypeScript, Amazon SES v2 SDK, Terraform, AWS IAM, Vercel environment variables.

## Global Constraints

- Do not require sign-in for the core safety check.
- Do not add SMS OTP, OAuth, trusted contact auto-notification, or automatic sharing in this PR.
- Do not store raw OTPs in DynamoDB.
- Email delivery must fail explicitly when not configured; never pretend a code was sent.
- SES sender verification may require an out-of-band AWS console or DNS verification step after Terraform apply.
