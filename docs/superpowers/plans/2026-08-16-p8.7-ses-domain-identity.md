# P8.7 SES Domain Identity Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let Terraform manage the `asksafe.ai` Amazon SES domain identity while the app sends setup OTP emails from `no-reply@asksafe.ai`.

**Architecture:** CloudFormation scopes the GitHub Actions Terraform role to one SES identity. Terraform creates the SES identity and outputs Vercel runtime values. Cloudflare remains a manual DNS step for DKIM CNAME verification.

**Tech Stack:** AWS SES, CloudFormation, Terraform, GitHub Actions, Vercel environment variables, Cloudflare DNS.

## Global Constraints

- AskSafe Home's core safety check must remain usable without sign-in.
- Do not use a personal Gmail address as the production setup email sender.
- Verify `asksafe.ai` as the SES identity and send from `no-reply@asksafe.ai`.
- Cloudflare DKIM records are added manually and must be DNS-only.
- Do not add Cloudflare Terraform provider in this PR.
- Do not modify product UI in this PR.
