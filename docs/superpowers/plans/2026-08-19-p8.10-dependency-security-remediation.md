# P8.10 Dependency Security Remediation Plan

## Goal

Reduce the Dependabot alert surface without changing AskSafe Home product
behaviour or weakening its security controls.

## Scope

1. Upgrade direct security-sensitive dependencies to patched versions.
2. Remove the unused `shadcn` CLI package only if its stylesheet import can be
   safely removed without changing the product's design tokens or Tailwind
   behaviour.
3. Regenerate `pnpm-lock.yaml` with the repository's package manager.
4. Verify the TypeScript check, safety-rule test suite, production build, and
   dependency audit where the environment permits it.

## Non-goals

- No product UI or workflow changes.
- No changes to AWS, SES, Bedrock, DynamoDB, or authentication behaviour.
- No claim that every Dependabot alert is closed until GitHub completes its
  post-push scan.

## Acceptance Criteria

- Next.js and PostCSS resolve to patched versions for the reported advisories.
- The lockfile no longer contains avoidable transitive packages from an unused
  CLI dependency.
- Existing tests and production build pass.
- The PR documents any residual advisories and their ownership.

## Verification

- `pnpm audit --json` reported `0` advisories after the lockfile refresh.
- In an isolated Linux copy of the repository:
  - `pnpm install --frozen-lockfile --ignore-scripts` passed.
  - `pnpm run lint` passed.
  - `pnpm run test:rules` passed.
  - `pnpm run build` passed.
- `git diff --check` passed.

## Residual Follow-up

GitHub Dependabot calculates alerts from the pushed dependency graph. It should
be checked again after this branch is pushed and its dependency submission has
completed. This remediation intentionally makes no product, AWS, SES, Bedrock,
or authentication workflow changes.
